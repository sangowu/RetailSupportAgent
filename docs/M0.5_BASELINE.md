# M0.5（三）冻结 baseline-v1

M0.5 的最后一个主题：把 M0 的成绩固定成一个**可比对象**，并让 CI 守住它不被悄悄改动。
前两篇见 [M0.5（一）成本与观测](M0.5_OBSERVABILITY.md)、[M0.5（二）本地启停](M0.5_LOCAL_DEMO.md)。

```
evaluation/baselines/baseline-v1/
    baseline.json      基线记录（数字全部由脚本现算）
    checksums.sha256   依赖文件的摘要，分 tracked / local_only 两段
```

```bash
uv run python scripts/freeze_baseline.py            # 生成 / 重新冻结
uv run python scripts/freeze_baseline.py --verify   # 只校验（CI 跑这个）
```

## 2. 三个刻意的取舍

### 2.1 运行目录写死，不取"最新一轮"

`BASELINE_RUN` 是脚本里的常量。基线的意义恰恰在于它**不会**跟着最新一次运行漂移；
要换基线就改这个常量，并且必须在 PR 里说清为什么换。测试里也写死了同一个值——
两边都改才算换基线，单边改动会立刻变红。

### 2.2 成本不冻结进基线

价格快照会随时间新增条目。把「每题 0.0806 元」抄进 `baseline.json`，
它会在某次调价后悄悄过期，而**没有任何东西会提醒你**。

所以成本以 `scripts/analyze_eval.py` 现算为准（口径见 [M0.5（一）](M0.5_OBSERVABILITY.md)），
基线只冻结成绩、评测栈与上游固定点。有一条测试钉着"基线里不许出现成本字段"。

### 2.3 校验和分两段

| 段 | 内容 | 校验规则 |
|---|---|---|
| `tracked` | 入库文件：任务集、上游 manifest、schema、那一轮的 summary | 缺失或变动都算失败，**CI 校验这一段** |
| `local_only` | 原始逐题轨迹（约 100KB/题，按 `.gitignore` 不入库） | 摘要照记；**缺失不算失败**，变了才算 |

不分段的话，CI 会因为原始轨迹本来就不该在仓库里而**永远红**——
一个恒红的门禁等于没有门禁。

实测三种情形：

```
原始轨迹不在本机   -> 通过，并报告「2 个不在本机——按设计不入库，不算失败」
改动 summary.json  -> 失败，退出码 1，指名道姓说哪个文件变了
还原后             -> 通过
```

## 3. 顺带订正一个对外报过的错数字

冻结前重算成本时发现：**每题成本 0.0716 元是错的，正确值是 0.0806 元。**

```
0.0716 = 3.2241 ÷ 45     ← 分母错了
0.0806 = 3.2241 ÷ 40     ← 这一轮只有 40 题
```

45 从哪来：这一轮有 5 道题因服务端额度故障没跑起来，后来用 `resume_run.py` 补跑。
补跑会让同一道题在结果文件里留下**两条**记录（先前失败的那条和补跑成功的那条），
去重前被算作 45 次模拟。去重在 PR #5 已经修好，但**当时没有回头重算已经写进文档的数字**。

影响：README 与 M0.4 实验方案里的每题成本偏低 11%；由它推出的
「qwen3.8-max 贵 5.4 倍」实为 **4.8 倍**。结论方向不变（成本仍不在一个量级，
选型仍是成本决策），但数字本身是错的，已全部改正并在 M0.4 文档里留下订正说明。

这也是基线脚本**不从文档抄数字、一律从原始结果现算**的直接原因，
以及为什么有一条测试专门盯着「分母必须是题数，不是模拟记录条数」。

## 4. CI 门禁的变化

`evaluation-gate` 作业从「N/A，不产生任何数值」换成真的做一件事：

```yaml
- name: 校验 baseline-v1 的校验和
  run: uv run python scripts/freeze_baseline.py --verify
```

它**仍然不跑评测**——跑一轮要真实计费，CI 里跑不起也不该跑。它守的是基线本身
没被悄悄改过：任务集、上游 manifest、那一轮的 summary 任何一个变了，
基线就不再代表它自称的那次运行，后续所有对比也就失去意义。

## 5. 与归档规范的一处偏差

`EVALUATION_AND_GATES.md` 建议路径 `artifacts/baselines/baseline-v1/`。
这里用的是 `evaluation/baselines/baseline-v1/`：原文写的是"建议路径模式"而非强制，
而本仓库的实验产物（`results/`、`task_sets/`、`schemas/`、`demo_runs/`）已经全在
`evaluation/` 下。再开一棵 `artifacts/` 树只会让同类东西分居两处。
AWS 阶段复制到 S3 时按规范的 key 前缀走，不受本地目录名影响。

## 6. 明确未做的事

- **没有性能对比门禁**。有了基线只是有了可比对象；真正的"候选 vs 基线"对比要
  真实跑评测，那是 M5 的主题，且必须显式授权计费。
- **基线只覆盖 holdout 40 题**。114 题全集从未在干净评测栈上跑过。
- **只有一个模型在这个栈上测过**。选型是成本决策，不是质量比较，理由见
  [M0.4 §9.9](M0.4_EXPERIMENT_PLAN.md)。
- **原始逐题轨迹没有异地备份**。它们只在本机，`.gitignore` 挡着不入库；
  规范里"AWS 阶段复制到 S3 并校验"尚未做。摘要已记，丢了能发现，但找不回来。
