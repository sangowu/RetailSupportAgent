## 1. 结论摘要

**五个候选模型全部可调用，请求的精确模型 ID 与响应返回的 ID 完全一致**，无别名回退、无静默替换。
工具调用链在五个模型上全部走通——这是 LangGraph 单 Agent 方案的前提，现已验证，不再是假设。

但**文档与实测有三处不一致**，直接影响 M0.4 的实验设计（见第 3 节）。

## 3. 与文档不一致之处（三项，均以服务端响应为证据）

### 3.1 「`reasoning_effort` 与 `thinking_budget` 互斥」只有 2/5 强制

同时传两个参数时：

| 模型 | 服务端行为 | 实际生效的参数 |
|---|---|---|
| `qwen3.8-max` | **拒绝**（400） | — |
| `qwen3.8-flash` | **拒绝**（400） | — |
| `qwen3.7-max-2026-06-08` | 静默接受 | `thinking_budget`（思考 64 tok） |
| `glm-5.2` | 静默接受 | `thinking_budget`（思考 64 tok） |
| `deepseek-v4-pro-0813` | 静默接受 | `reasoning_effort`（思考 68 tok） |

三个模型不但不报错，**"谁覆盖谁"的方向还不一致**。代码里绝不能依赖这条互斥规则，
必须由调用方保证只传其一——否则同一份配置在不同模型上会产生不同的思考行为，
而且没有任何报错提示。

### 3.2 `deepseek-v4-pro-0813` 不遵守 `thinking_budget`

设 `thinking_budget=64`，实测 `reasoning_tokens = 106`，**超出上限 65%**。
其余四个模型都落在 64 或以内（qwen3.8-max 为 61）。

这意味着该模型上的思考预算是"建议"而非"上限"，成本无法通过该参数封顶。
M0.4 若把它纳入预算对比，必须以**实测 token 数**计费，不能按设定值推算。

### 3.3 `qwen3.7-max-2026-06-08` 不支持 `max` 档

服务端明确给出允许值：`none`、`minimal`、`low`、`medium`、`high`、`xhigh`。
其余四个模型接受 `max`。参照模型与候选模型的档位空间不同，**逐档比较不能用同一组档位**。

同时，从服务端报错反推出该模型的档位映射：

| 档位 | 映射的 thinking_budget |
|---|---|
| `low` | 8192 |
| `medium` | 32768 |

这是唯一一处能从外部读到档位真实预算的地方（见 4.2）。其余模型在小上限下就能跑通，
没有暴露数字——**"未暴露"不等于预算为零**。

## 4. 方法学记录

### 4.1 第一版探针有缺陷，已修正

初版把 `max_completion_tokens` 设为 512 去测各档位，结果 `low`/`medium` 报 400，
险些被记成"该模型不支持这两档"。实际报错原文是：

```
max_completion_tokens [512] must be greater than thinking_budget [8192]
```

——被拒的原因是**总输出上限不够**，不是档位不支持。这正是 `MODEL_EXPERIMENTS.md`
要求区分的"思考不够"与"总输出不够"。修正后的档位探针不设 `max_completion_tokens`。

### 4.2 把缺陷变成了测量手段

既然服务端会在报错里写出档位映射的预算数字，就专门保留一个**故意压低上限**的探针
`effort_budget_mapping_*`：报错即证据。这是目前唯一能从外部读出"某档位等于多少 token"的途径，
且因为请求被拒，几乎不产生费用。

### 4.3 证据不足之处，明确标注

各档位实测的 `reasoning_tokens` **不随档位单调上升**（例如 `qwen3.7-max` 的
`low`=226 > `xhigh`=174）。

**不能据此断言档位无效。** 每档只跑了 1 次、提示词极短，波动完全可能来自采样噪声。
档位是否真正影响行为，必须在 M0.4 用真实 τ²-bench 任务、重复采样后再判断。
本报告只记录"参数是否被接受"与"单次观测值"，不给出档位有效性结论。

同理，`minimal` 档在 `qwen3.7-max` 与 `glm-5.2` 上 `reasoning_tokens` 为空，
且 `glm-5.2` 只输出 3 个 token——该档位可能产出不可用的回答，M0.4 需单独确认。

## 6. 对后续阶段的直接影响

1. **M0.3**：工具调用链五模型全通，LangGraph 单 Agent 方案无接口层阻塞，可以开工。
2. **M0.4**：
   - 思考配置必须**只传一个参数**，由代码强制，不依赖服务端互斥检查。
   - 档位比较不能假定五模型共享同一档位集合（`qwen3.7-max` 无 `max`）。
   - 成本一律按**实测 token** 计算，`deepseek-v4-pro-0813` 尤其不能按预算设定值推算。
   - 档位有效性需重复采样，本阶段数据不足以支撑任何淘汰决定。
3. **模拟用户与 NL 评判模型尚未选定**，仍是 M0.4 的前置项。
