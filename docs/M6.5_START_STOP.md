# M6.5: two commands an operator actually runs

## 0. Why this step exists

M6's acceptance line is "Terraform, one-command start/stop". M6.4 did the Terraform. What
is missing is the part someone uses: the environment exists, and starting it before a
demonstration means remembering an instance id, running `aws ec2 start-instances`, waiting
for something unspecified, and looking up an address that changed since last time.

The pieces are all measured. Starting a stopped instance takes 41 seconds to the API
answering (M6.2). The application says whether it is busy (M6.3). The address is in
Terraform's outputs (M6.4). Nothing here is new capability; it is the difference between a
system that works and a system somebody can use.

## 1. Change card

- **Stage and step**: M6.5
- **Type**: feature
- **The specific problem**: starting and stopping a demo is four remembered commands and a
  lookup, and stopping it has nothing that checks whether anyone is mid-conversation
- **The single theme of this change**: the operator's entry points. No change to the
  environment, the image or the application.
- **Control variables this change does not touch**: the Terraform, the instance files, the
  application, the agent, the guard, the evaluation harness and every baseline. The
  commands drive what M6.4 already builds.
- **Explicitly out of scope**, each its own later step:
  - HTTPS and a stable address
  - Archiving before a teardown, and rollback between image versions
  - GitHub Actions. Who may run these is separate from what they do.
- **Expected benefit**: a demonstration begins with one command and ends with one, and
  ending one cannot interrupt work in progress.
- **Possible cost**: a command that refuses to stop is a command that can leave a machine
  running. Section 1.3 says what bounds that.

### 1.1 Why there is no archive step before stopping

`docs/OPERATIONS.md` describes stopping a demo as: drain, export, verify the export,
destroy, confirm. That was written for a shape where stopping means destroying, so the
export is the only copy that survives.

M6.1 chose differently. Stopping stops an instance; the volume, the database and the image
stay exactly where they are, and the next start reads the same rows. **Nothing is lost by
stopping, so nothing has to be exported first.** Archiving belongs to `terraform destroy`,
where the volume does go away, and that is a later step.

Saying this here rather than quietly omitting the step: the acceptance list still has
archiving on it, and this card is not the one that satisfies it.

### 1.2 What each command does

| Command | |
|---|---|
| `status` | where the instance is, and if it is running, what the application says about being busy |
| `start` | start it, wait until both ports answer, print the addresses |
| `stop` | refuse if work is unfinished, otherwise stop it |

**`start` waits for an answer, not for a state.** `running` means the hypervisor has the
machine; the demo is not usable until the API and the UI reply, which M6.2 measured at 41
seconds after that. A command that returns early is a command that hands someone a broken
link.

**`stop` reuses the idle verdict rather than inventing a second definition.** M6.3 already
decides what "busy" means for this application: writes awaiting confirmation, approvals
awaiting a human, open tickets. An operator stopping the machine and the watcher stopping
the machine must agree, or one of them is wrong.

**The address is read at the time, never remembered.** This shape uses no Elastic IP, so
the public address changes across every stop.

### 1.3 The refusal, and its bound

`stop` refuses while the application reports something holding it open, and says what. That
is deliberately the same failure the watcher has: an environment with a stuck ticket would
never stop.

Two things bound it. The instance's own uptime cap still fires whatever anyone thinks
(M6.3), and `--force` exists for a person who has looked at the reason and decided. A force
that is silent would be a footgun, so it prints what it is overriding.

### 1.4 What is measured, and the thresholds

| Metric | Threshold |
|---|---|
| `start` on a stopped instance to both ports answering | under 120 seconds, M6.1's rule |
| `start` on an instance that is already running | returns promptly, changes nothing |
| `stop` while the application reports work | refuses, names the reason, exit code says so |
| `stop` when idle | the instance reaches `stopped`, and the containers were stopped first |
| `status` with no instance | says so plainly rather than failing on an index |
| The existing suite | passes unchanged |

### 1.5 How it stays testable

The decisions are pure functions of what AWS and the application reported: what to do given
an instance state, and whether a stop may proceed given an idle answer. Those are tested
directly. The AWS calls are one thin layer that the tests replace, in the way
`scripts/aws_inventory.py` already shells out to the CLI.

### 1.6 Baseline and previous version

No previous version: no such command exists. The reference is M6.2's 41-second restart and
M6.3's idle verdict, both of which this drives rather than changes.

## 2. Implementation and verification

### 2.1 Files

| File | Responsibility |
|---|---|
| `scripts/demo.py` | `status`, `start`, `stop`, and the decisions behind them |
| `tests/test_demo_commands.py` | 21 tests over those decisions |
| `docs/OPERATIONS.md` | the two commands, and when each refuses |

### 2.2 How the instance is found

By its tags, not by an id out of Terraform's state. A demo can then be stopped from a
machine that never initialised the backend, and by someone who is not the person who
applied it. Terminated instances are excluded from the query: they keep their tags for a
while, and a terminated instance is not an environment.

Two instances carrying the demo tags is refused rather than resolved. Acting on an
arbitrary one of two environments is the worst available answer, so the tool names both and
stops.

### 2.3 Exit codes mean different things

| Code | |
|---|---|
| 0 | it happened, or there was nothing to do |
| 1 | it could not be done: no environment, or a machine in motion |
| 2 | it was refused because work is unfinished |

Two is separate from one because a refusal is a decision the tool made, not a failure. A
script wrapping this can retry on 1 and must not on 2.

### 2.4 The stop is graceful without doing anything

`aws ec2 stop-instances` sends the machine an ACPI shutdown. systemd stops `rsa.service`,
whose `ExecStop` runs `docker compose down`, so PostgreSQL closes its files. This tool does
not need to stop the containers itself, and does not.

## 3. Comparison

No model is called and no task set is run, so task success rate, safety violations and cost
per successful task are unchanged by construction.

### 3.1 Driven against a real environment

One `t3.small` in `eu-west-1`, created by M6.4's Terraform.

| What was run | Result |
|---|---|
| `status`, no environment | "no demo environment", exit 0 |
| `start`, no environment | points at the Terraform README, exit 1 |
| `start` while stopping | "is stopping; wait for it to settle", exit 1 |
| `start` from stopped | ready in 29 s, then 35 s on a second run |
| `status` while running and idle | both addresses, and "idle" |
| `status` with a ticket open | "busy: 1 open ticket(s)" |
| `stop` with a ticket open | "not stopping, work is unfinished: 1 open ticket(s)", exit 2 |
| `stop --force` | "stopping anyway, overriding: 1 open ticket(s)", exit 0 |
| `stop` when already stopped | "is already stopped", exit 0 |
| Instance reaching `stopped` | 25 s |

**29 and 35 seconds against a 120-second threshold.** M6.2 measured 41 seconds for the same
thing by polling directly, so the command adds nothing measurable.

**The address changed three times** across those stops: `3.254.134.69`, then
`108.131.104.240`, then `3.252.101.236`. That is why it is read at the time and never
remembered.

### 3.2 Stopping loses nothing, checked rather than argued

Section 1.1 says there is no archive step because a stop keeps the volume. The ticket opened
for the refusal test was still there after the instance was forced down and started again:

```
{"holding":["1 open ticket(s)"],"open_tickets":1,"persistent":true}
```

Same row, same database, after a full stop and start.

### 3.3 Against the thresholds

| Metric | Threshold | Result |
|---|---|---|
| `start` to both ports answering | under 120 s | 29 s and 35 s |
| `start` on a running instance | prompt, changes nothing | reports it and shows status |
| `stop` while work is unfinished | refuses, names it, exit code says so | refused, named the ticket, exit 2 |
| `stop` when idle | reaches `stopped`, containers first | 25 s, through systemd's `ExecStop` |
| `status` with no instance | says so plainly | "no demo environment", exit 0 |
| The existing suite | unchanged | 596 tests, 0 failures, 0 errors |

### 3.4 One case checked by test and not on the instance

`stop` must refuse when the application does not answer at all. The live attempt to catch
that raced the boot: by the time the command ran, the API had come up and answered, so the
stop correctly proceeded. Rather than spend another instance on a timing window, that path
is covered by `test_silence_is_not_permission` and `test_force_works_when_the_application_never_answered`.

## 4. Failure analysis and conclusion

**PASS.** A demonstration begins with one command and ends with one, and ending one cannot
quietly interrupt work.

- **What was accepted**: `scripts/demo.py` and 21 tests.
- **What was not built, and why it is not an omission**: an archive step before stopping.
  M6.1's shape keeps the volume, section 3.2 shows the rows survive, and archiving belongs
  to the teardown that removes the volume.
- **What is left running**: the demo environment, stopped. That is its designed steady
  state and it costs the 10 GiB volume, 0.88 USD a month. `terraform destroy` removes it,
  and one `apply` builds it again in about two minutes.

### 4.1 Not verified

- **A stop during an actual conversation.** Every check here used a ticket in the database
  rather than a person mid-sentence. The verdict is the same one M6.3 measured, but the
  human case was not run.
- **Two operators at once.** Nothing coordinates two people running `stop` and `start`
  together; EC2 would serialise them, and what each command then prints was not looked at.
- **The refusal on silence, live**, per section 3.4.
- **HTTPS.** The addresses printed are plain HTTP, reachable only from the addresses in
  `allowed_cidrs`. Until that changes, the URLs this prints should not be sent to anyone.
- **Anything about who may run this.** It uses whatever credentials the operator has.
